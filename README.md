# Описание решения

Запуск: Python 3.9.13. Скрипт создаёт `submission.csv`. Я зафиксировал все seed поэтому повторный запуск даёт тот же файл. Признаки строятся в `features.py`, обучение и валидация — в `solution.py`

LLM и внешние API я не использовал

## Подготовка событий

- взял только события внутри окна наблюдения (`window_start_ts <= event_ts < window_end_ts`). Около 12% событий лежат после окна, их я отбросил
- события `captcha_shown` встречаются только после окна, то есть это утечка. В признаки их не включал
- удалил полные дубликаты строк и отсортировал события по времени внутри каждой куки
- привел `platform` к трём значениям: web, android, ios
- из `user_agent` взял семейство клиента и мажорную версию. Сырую строку не использовал

## Признаки

По событиям каждой куки я считаю 98 признаков, по одной строке на куку:

- Ритм:кКвантили и разброс интервалов между событиями, их автокорреляция, доля уникальных интервалов и минут, время на странице
- Курсор (web): разброс и размах координат, шаг между событиями, доля событий без курсора
- Состав событий: доли типов событий, воронка (фото, контакты, избранное на один просмотр), энтропия
- Разнообразие: число городов и категорий, их энтропия и частота переключений, глубина листания выдачи, повторные просмотры
- Популярность объявлений: сколько других кук смотрели те же объявления за 7 дней до конца окна (на 1000 активных кук) и сколько кук делят с этой кукой 2 и более объявления. Разметку и будущие события здесь не использовал
- Кука и клиент: возраст куки, время от создания куки до первого события, семейство UA, платформа

## Валидация

Тест лежит позже train по времени, поэтому я валидировался по схеме forward-chaining: модель учится на днях до фолда и проверяется на следующих днях. Фолды: 13–14.04, 15–16.04 и 17–19.04. Метрику считал официальной функцией `precision_at_recall`

Результаты (P@R≥0.7, среднее по 3 фолдам):

- Baseline (`n_events` и `item_nunique`, LightGBM): 0.109
- Без признаков популярности: 0.744
- Итоговая модель (все признаки, LightGBM, среднее по 5 seed): 0.823, ROC-AUC 0.945

## Что я пробовал

- Разные гиперпараметры. Получил 0.80–0.83. Различия в пределах шума фолдов поэтому оставил параметры по умолчанию
- Без UA и платформы. Качество почти не меняется, т.е модель опирается на поведение
- Без возраста куки. Качество падает до 0.81
- Популярность с учётом будущих дней. Отказался, потому что утечка

## Ограничения

- В каждом фолде около 200 ботов, поэтому оценка шумная (+-0.03)
- Хуже всего ловятся боты на андроиде: у них нет курсора
- Признаки популярности не помогут против сервиса, который обходит уникальный набор объявлений
